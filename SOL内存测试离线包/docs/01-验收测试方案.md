# DDR5 内存条整机验收压测方案（Windows）

> 适用场景：将 DDR5 内存条插入个人电脑（Windows 系统）后，进行整机验收级压力测试，验证内存在标称规格（XMP 3.0 / EXPO）下的稳定性和可靠性。

---

## 1. 验收目标与标准

| 项目 | 要求 |
| --- | --- |
| 验收目标 | 内存在标称频率（XMP 3.0 / EXPO）下无错误、长时间稳定运行 |
| 通过标准 | 独立引导诊断 4 轮 0 错误 + 系统级压测 0 错误 |
| 温度要求 | DDR5 模组温度全程 < 60℃ |
| 测试时长 | 约 1 天（过夜独立诊断 + 白天系统级压测） |

---

## 2. 测试工具与分层架构

| 阶段 | 工具 | 授权 | 测试内容 | 优先级 |
| --- | --- | --- | --- | --- |
| ① 独立引导诊断 | Memtest86+ v9 | 开源 GPLv2 | 物理存储单元、地址线、数据保持（bit fade）；绕过操作系统，覆盖几乎全部物理内存 | 必测 |
| ② 系统级压力 | TestMem5 (TM5) | 闭源免费 | 内存控制器、总线、真实负载稳定性（超频圈标准） | 必测 |
| ② 系统级压力 | Prime95（Blend 模式） | 闭源免费 | CPU + 内存协同压力 | 必测 |
| ② 系统级压力 | OCCT（Memory 测试） | 闭源免费 | 内存子系统压力、错误检测 | 建议 |
| ③ 温度监控 | HWiNFO64 | 免费 | DIMM 温度、VDD/VDDQ 电压监控与日志 | 全程 |

> 说明：
> - **Memtest86+（开源）与 MemTest86（PassMark 闭源）**是同源的两个分支，本方案使用开源的 Memtest86+。
> - 系统级测试无法覆盖操作系统本身占用的内存，且错误可能被系统缓存掩盖，因此以第 ① 阶段的独立引导诊断为主要判定依据。

---

## 3. 测试时长参考

> 以下为 32GB DDR5、多核并行（SMP）、跑全部 13 项测试的典型时长估算，实际以当前机器为准。

| 测试 | 单轮（1 PASS）时长 | 建议总时长 |
| --- | --- | --- |
| Memtest86+ | 约 30–60 分钟（第 1 轮更快，用于快速抓严重错误；后续轮次更深入、更慢） | 4 轮约 2–4 小时 |
| TM5 + anta777 Extreme | 约 30–60 分钟/循环 | 3 轮约 1.5–3 小时 |
| Prime95 Blend | 无“轮”概念，持续运行 | 建议 1 小时 |
| OCCT Memory | 无“轮”概念，持续运行 | 建议 1 小时 |

影响时长的关键因素：

- **容量翻倍 ≈ 时长翻倍**：64GB 大致为 32GB 的两倍；128GB 建议按过夜规划
- **CPU 核心数**：开启多核并行（SMP，按 `F2`）后墙钟时间明显缩短（单轮总工作量不变，但由多核分摊）
- **轮次深度**：第 1 轮偏快，2–4 轮更深入，总时长约为第 1 轮的 2–3 倍（官方示例：1 轮约 15 分钟 vs 4 轮约 120 分钟）
- **频率/时序**：高频紧时序下每轮略长，但差异不大

**整体安排建议**：Memtest86+ 4 轮放**过夜**运行，白天再跑 TM5 + Prime95 + OCCT，一天内完成验收。

## 4. 详细执行步骤

### 4.1 制作启动 U 盘（约 10 分钟）

1. 下载 Memtest86+ v9 ISO：<https://memtest.org/>（免费、开源）
2. 准备一个 ≥1GB 的 U 盘（写入会清空数据，注意备份）
3. 使用 **Rufus** 写入：
   - 设备：选择目标 U 盘
   - 引导类型：选择“镜像文件”，指向下载的 ISO
   - 分区类型/目标系统：按默认（UEFI）
   - 点击“开始”，等待写入完成

### 4.2 BIOS 设置

1. 开机按 `DEL` / `F2` 进入 BIOS
2. **开启 XMP 3.0 / EXPO**，使内存运行在标称频率（按购买的规格验收）
3. 确认内存容量、频率、双通道/满插槽均被正确识别
4. 将 U 盘设置为第一启动项（或使用启动菜单快捷键直接选择 U 盘）

### 4.3 Memtest86+ 独立诊断（2–4 小时 / 建议过夜）

1. 从 U 盘启动进入 Memtest86+
2. 按 `F1` 进入配置菜单，确认全部测试选中（Test 0–13，默认全选）
3. 按 `F2` 开启多核并行（SMP），缩短测试耗时
4. 保持默认 **4 轮 PASS**；间歇性故障建议过夜运行
5. 判读结果：
   - **通过**：`Errors: 0`，且 `Pass` 计数正常递增
   - **报错**：记录错误地址（Error Address）、测试号、错误类型，进入第 5 章排查流程

### 4.4 系统级压力测试（Windows 内）

1. **TestMem5 (TM5)**
   - 下载 TestMem5，加载 **anta777 Extreme** 配置文件
   - 运行 **3 轮完整循环**，要求 0 错误
2. **Prime95**
   - 选择 **Blend 模式**（同时压测 CPU 与内存）
   - 运行 **1 小时**，无蓝屏、无错误 Worker 即通过
3. **OCCT**（可选）
   - 选择 Memory 测试，运行 **1 小时**
   - 关注是否报错、蓝屏或重启

### 4.5 温度监控与记录

1. 全程运行 **HWiNFO64**，记录：
   - DIMM 温度（各插槽）
   - VDD / VDDQ 电压
   - 内存时钟频率
2. 判稳温度上限：**60℃**。DDR5 的 PMIC 发热明显，超温优先改善机箱风道后再继续测试
3. 保存 HWiNFO 日志（CSV）作为验收记录

---

## 5. 报错排查流程

若第 4.3 / 4.4 步出现任何错误，按以下顺序逐层隔离：

1. **单条单槽隔离测试**：拔到只剩一根内存，依次在 A1 / B1 等槽位单独测试；逐根条、逐槽位复测，定位问题条或问题槽
2. **降频复测**：关闭 XMP/EXPO，以默认 JEDEC 频率再跑一轮——区分“内存本身损坏”与“标称频率不稳”
3. **结论分支**：
   - 默认频率也报错 → 内存条本体问题，考虑更换
   - 仅 XMP/EXPO 下报错 → 超频不稳，尝试放宽时序或适当调整电压
   - 单条全过、满插槽报错 → 检查插槽与主板内存兼容性（QVL 列表）
4. **主板与系统因素**：过热 CPU、电源供电不足也可能导致间歇性内存错误，结合 HWiNFO 日志排查

## 8. 批量验收流程（1000 根全检 + 智能识别）

> 适用场景：对 1000 根 DDR5 内存条做 **100% 全检**（每根都测），并针对混合来源（厂家新件有/无报告、二手件等）采用差异化测试深度 + 智能识别自动分类路由。

### 8.1 总体工作流

```
每根条子贴唯一 ID
   │
   ▼
① 智能识别（自动）──── 每批插满槽 → 自动采集 SPD → 规则分类
   │  识别：DDR5 类型、容量、频率、厂商、型号(PartNumber)、序列号、
   │        XMP 3.0 / EXPO、SPD 是否有效、是否匹配预期清单
   │  输出：正常 / 待复核（无序列号、非 DDR5、容量不符、不在预期清单等）
   ▼
② 混合路由（差异化测试深度，但每根都测 = 100% 全检）
   │  ├─ 正常件（有报告新件优先）→ 批量快速筛选轮（1 轮，整批同时跑）
   │  └─ 待复核件（无报告/二手/识别异常）→ 单根深测（多轮/过夜）+ 人工复核
   ▼
③ 结果自动回写 → 1000 根逐根 pass/fail 总表（按唯一 ID 可追溯）
```

### 8.2 智能识别（自动分类）

使用脚本 **`Identify-Memory.ps1`**（与本方案同目录），插满槽位后运行即可自动采集每根内存信息并分类：

```powershell
# 基本识别（生成当前批次清单）
.\Identify-Memory.ps1 -BatchName "batch01"

# 带预期清单匹配（清单需含 SerialNumber 列，可加 Capacity 列校验容量）
.\Identify-Memory.ps1 -ExpectedCsv "C:\path\expected.csv" -BatchName "batch01"
```

自动识别的字段：槽位、序列号、型号、容量、频率、内存类型（是否为 DDR5）等。

| 分类规则 | 判定结果 |
| --- | --- |
| SPD 有效 + 序列号/型号/容量齐全 + 与预期清单匹配 | **正常** → 批量快速筛选 |
| 非 DDR5 | **待复核** → 深测 + 人工复核 |
| 序列号缺失 / 型号缺失 / 容量读取异常 | **待复核** → 深测 + 人工复核 |
| 不在预期清单 / 容量与预期不符 | **待复核** → 深测 + 人工复核 |

每次运行生成带时间戳的批次 CSV（`memory_results\<批次>.csv`），累积形成验收数据库。

### 8.3 混合路由策略（测试深度分配）

| 条子状态 | 测试方式 | 深度 |
| --- | --- | --- |
| 正常件（有出厂报告的新件） | 批量快速筛选轮（Memtest86+ 1 轮，整批同时跑） | 浅，全覆盖 |
| 正常件（无报告） | 批量快速筛选轮 + 抽加深度复核 | 中 |
| 待复核件（二手 / 识别异常 / 无序列号） | 单根深测（多轮 / 过夜）+ 人工复核 | 深 |

> 所有条子无论分类如何都至少经过一轮快速筛选，满足 **100% 全检**要求；差异化只体现在深度与复核比例上。

### 8.4 吞吐量参考（100% 全检，仅跑快速筛选轮）

| 电脑配置 | 每批根数 | 快速筛选轮 | 1000 根耗时 |
| --- | --- | --- | --- |
| 1 台 4 槽 PC | 4 | 25–40 分钟 | 约 2 周（每天 10h） |
| 1 台 8 槽主板 PC | 8 | 40–60 分钟 | 约 4–7 天 |
| 2–3 台 8 槽 PC 并行 | 16–24 | 同上 | 约 2–3 天 |

> 全检不做每根过夜 4 轮；失败件才升级为深测复核。若时间不允许，建议将全检外包第三方模块级测试。

### 8.5 批量验收记录要求

- 每根条子以唯一 ID（序列号或贴标）关联测试结果，形成逐根可追溯的 pass/fail 总表
- 记录字段：唯一 ID、来源类别、槽位、SPD 数据、分类结果、测试日期、测试轮次、结果、失败详情（错误地址/测试号）
- 失败件单独登记并进入第 5 章排查流程；全部通过后汇总输出验收报告
