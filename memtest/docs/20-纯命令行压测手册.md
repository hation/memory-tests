## 测试周期评估（排期用，含 MONITOR_TEMP / RESTART_LOOP）

> 基准：被测服务器 **64GB · Hygon**；memtest 全项每轮 ≈ 1.5–2h（含较慢的随机/模 20 项）。

**档位基准时长**：

| 档位 | 时长 |
| --- | --- |
| 1轮快筛（前 9 项 × 1 轮） | ≈ 68 分钟（srv01-a1-r1 实测） |
| 1轮全项（13 项 × 1 轮） | ≈ 1.5–2h |
| 2轮全项 | ≈ 3–4h |
| 4轮全项（验收口径） | ≈ 6–8h |

**附加参数增量**：
- `MONITOR_TEMP`：**+秒级**（报告前读一次 IPMI 温度，不全程采样）→ 可忽略
- `RESTART_LOOP=N`：**+N×90 秒**（每次断电后等 90s）→ 200 次 = **+5h**（唯一显著大头）
- `MONITOR_ECC`：+秒级（读 WHEA 事件）→ 可忽略

**组合场景总耗时**（一条编排器命令带全参数）：

| 场景 | 构成 | 合计 |
| --- | --- | --- |
| 2轮全项（默认配置带 ECC/Temp） | 3–4h + 秒 | ≈3–4h |
| 4轮全项（验收口径） | 6–8h + 秒 | ≈6–8h |
| 4轮全项 + 断电循环 200 | 6–8h + 5h | **≈11–13h** |
| 断电循环专项（1轮全项 + 200 次） | 1.5–2h + 5h | ≈6.5–7h |
| 72h ORT（流程 6） | 72h（内置 ORT 模式，不依赖 stress-ng）+ 10min 缓冲 | ≈72h + 10min |

> 排期要点：**RESTART_LOOP 显著加时**——断电循环单独跑专项（勿与 4 轮全项叠一起）；
> MONITOR_TEMP / MONITOR_ECC 无感，随便开。

## 流程 0 · 准备与校验（约 10 分钟，一次性）

**做什么**：环境自检 → BMC 链路 → 服务器能力评估。

**命令**（编排机）：
```powershell
cd C:\memtest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check_env.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Diag-Bmc.ps1 -BmcHost 10.0.0.10 -BmcUser root
```
**命令**（能力评估 = 两段式 + 合并，脚本自动按 BMC 可达性判角色）：
```powershell
cd C:\memtest
# ① 服务器本机（自动判为被测服务器，跑带内项，免密码提示）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-ServerAssessment.ps1 -MachineName srv01
# ② 编排机（自动判为编排机；不带 -VerifyPowerCycle，只读探测不重启服务器）——必须在能通 BMC 的编排机跑！
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-ServerAssessment.ps1 -BmcHost 10.0.0.10 -BmcUser root -MachineName srv01
# ③ 【可选】合并完整 17 项（先把另一台的 cap CSV 拷到本机同一目录；文件名已带角色后缀不会冲突）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-ServerAssessment.ps1 -MergeInband .\results\assessment\srv01-cap-被测服务器.csv -MergeOob .\results\assessment\srv01-cap-编排机.csv -MachineName srv01
```

> ⚠️ **③ 合并评估为可选步骤**：已人工确认 17 项能力时可跳过（无需在两台机器间来回拷贝 cap CSV）。跳过不影响任何测试结果或测试日志——`srv01-assessment.csv/.txt` 仅作排期参考，无脚本消费；验收以建档 + 各流程报告 + master_manifest 为准。若日后需要补合并，用"流程 10 结果归集"把服务器 cap CSV 带过来再跑 ③ 即可。

> ⚠️ **② 与上方 Diag-Bmc 必须在能通 BMC 的编排机上跑**；若误在服务器本机跑，会输出防护提示并判为"被测服务器(BMC 不可达)"——这是正常的物理约束（服务器本机到不了 BMC 管理网），换编排机跑即可。

**得到什么**：check_env 输出"全部 OK"；Diag 四步无 Error（④ 空闲无输出属正常）；两段各产 cap CSV（文件名带角色后缀）、合并后 17 项完整（服务器 ECC=True、混插已满足 2 槽、第 10 项"可测(命令可用，未实测)"——断电循环能力已确认，不重启；重启实测由流程 5 的 RestartLoop 完成）。

**日志在哪**：`C:\memtest\results\cmdlog\commands-<日期>.csv`（每步自动记录）+ 各运行机器 `results\assessment\<机器>-cap-<角色>.csv` + 合并报告 `results\assessment\srv01-assessment.csv/.txt`。

## 流程 2 · Memtest 压测（第 3 项）—— 编排机跑

**做什么**：SOL 远程抓 Memtest86+ 日志，跑满轮次自动出逐根报告。四档可选，每档 = **命令 `-MaxPasses` ↔ GRUB 菜单预设 ↔ 判读 `Passes` 一一对应**：

| 档位 | 命令 `-MaxPasses` | GRUB 菜单预设 | 测试内容 | 时长 |
| --- | --- | --- | --- | --- |
| 1轮快筛 | `-MaxPasses 1` | **1轮快筛** | 前 9 项 × 1 轮 | ≈68 分钟 |
| 1轮全项 | `-MaxPasses 1` | **1轮全项** | 13 项 × 1 轮 | ≈1.5–2h |
| 2轮全项 | `-MaxPasses 2` | **2轮全项** | 13 项 × 2 轮 | ≈3–4h |
| 4轮全项（验收口径） | `-MaxPasses 4` | **4轮全项** | 13 项 × 4 轮 | ≈6–8h |

**顺序铁律**：**先启动编排器（开 SOL 等日志）→ 再引导服务器**（Ventoy 或 BMC 虚拟介质挂 `C:\memtest\boot\memtest-sol.iso`，GRUB 菜单选对应预设）。顺序反了 = 白测。

> ⚠️ SOL 未收到输出/会话中断时，按序排查：① 引导方式必须是 BMC 虚拟介质挂载 memtest-sol.iso（Ventoy U 盘引导时串口走物理 COM，SOL 收不到）；② BIOS 串口重定向（Console Redirection → SOL）须开启，波特率 115200 三处一致；③ 残留 SOL 会话用 `sol deactivate` 清掉再跑；④ 编排机 ping 通 BMC，服务器本机 `Set-BmcStaticIp.ps1 -CheckOnly` 确认 IP 源静态。参考 docs/15 §3。

**命令**（编排机；选好档位后，`BatchName` / `-MaxPasses` / 菜单预设 三者必须一致；BatchName 是批次标签可自定义，建议带档位标识）：
```powershell
cd C:\memtest

# 1轮快筛（≈68 分钟）—— 菜单选「1轮快筛」
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-MemtestSuite.ps1 -BatchName srv01-a1-r1 -BootMethod SOL -BmcHost 10.0.0.10 -BmcUser root -MaxPasses 1 -ConfirmSwitch

# 1轮全项（≈1.5–2h）—— 菜单选「1轮全项」
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-MemtestSuite.ps1 -BatchName srv01-a1-f1 -BootMethod SOL -BmcHost 10.0.0.10 -BmcUser root -MaxPasses 1 -ConfirmSwitch

# 2轮全项（≈3–4h）—— 菜单选「2轮全项」
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-MemtestSuite.ps1 -BatchName srv01-a1-r2 -BootMethod SOL -BmcHost 10.0.0.10 -BmcUser root -MaxPasses 2 -ConfirmSwitch

# 4轮全项（验收口径，≈6–8h）—— 菜单选「4轮全项」
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-MemtestSuite.ps1 -BatchName srv01-a1-r4 -BootMethod SOL -BmcHost 10.0.0.10 -BmcUser root -MaxPasses 4 -ConfirmSwitch
```

**下一步做什么（命令输入后，按序执行）**：
1. **输入 BMC 密码**：没带 `-BmcPass` 时会提示 `BMC 密码（10.0.0.10）:`，输入密码回车（不回显）。
2. **编排器开 SOL 等待**：打印 `===== Memtest86+ 编排开始（批次: …，方式: SOL）=====` 后停在等待状态——此时**别动编排机**，它在等服务器输出。
3. **去引导服务器**：用 Ventoy U 盘或 BMC 虚拟介质挂载 `C:\memtest\boot\memtest-sol.iso`，在 GRUB 菜单选**与命令一致的档位预设**（如上表；`-MaxPasses 1` 若想要全项就选「1轮全项」，想快筛就选「1轮快筛」；`-MaxPasses 2` 选「2轮全项」，以此类推）。
4. **等待自动完成**：Memtest86+ 自动开跑，编排器全程抓 SOL 日志；跑满自动出报告，无需人工干预。
5. **判读报告**：看 `results\reports\<批次>-report.csv`——`Errors=0`、`Status=pass`、`Passes=N` 与你选的档位一致。

**得到什么**：编排器打印报告路径；判读 `Errors=0`、`Status=pass`、`Passes=N` 与所选档位一致。
> 注：全项/快筛预设已带 ECC 轮询（`ecc` 参数），测完报告 `EccErrors` 列直接反映服务器 ECC 错误数；mtlog 可查 `ev=ecc/ev=uecc` 明细。

**日志在哪**（编排机）：`C:\memtest\results\raw\<批次>.mtlog.txt`（原始日志）+ `results\reports\<批次>-report.csv`（逐根报告）+ `results\master_manifest.csv`（累计）。

> 常用默认参数（BMC 地址/用户、ECC/温度监控开关）已配置在 `config\memtest-suite.conf`，命令行可省略；显式指定则覆盖配置。

> ⚠️ 首次使用建议先跑一次 **5 分钟冒烟**（确认无人值守启动、无弹窗卡住、到点自动停），通过后再跑 2-4h 正式长压：
> ```powershell

> ```
> 判读 `reports\smoke-prime95-report.csv` 的 `Status=PASS`（运行期 CPU 满载、无弹窗卡住；脚本 `-Help` 亦有提示）。

**得到什么**：判读 `reports\srv01-a1-mix-prime95-report.csv` 的 `Status=PASS`（实际时长 ≥180 分钟 且 0 错误 且 非提前退出 且 CPU 活跃；未开始/卡对话框判 FAIL）+ Memtest 0 错误；单根不稳 → 单根隔离复测。
> 注：TM5 无 headless 接口、仅支持人工操作，降级为**可选人工**工具；离线验收以 Memtest + Prime95 脚本为准。

**日志在哪**：Memtest = 编排机 `results\reports\srv01-a1-mix-report.csv`；Prime95 报告 = **服务器本机** `results\reports\srv01-a1-mix-prime95-report.csv`（脚本自动合成 `master_manifest.csv`）；TM5 无固定路径（人工记录）。

## 流程 5 · 断电循环（第 10 项）—— 编排机跑

**做什么**：≥200 次断电-上电，验证 DDR5 上电训练稳定。

> ⚠️ 若编排机与被测服务器共用电源，断电循环可能把编排机网卡打坏（Code 43，2026-10-28 根因）；先把编排机换独立电源回路、停掉 SOL 会话再跑。

**第一步 · 确认断电循环命令可用（只读，不重启）**：编排机跑能力评估（不带 `-VerifyPowerCycle`）或 Diag-Bmc ②，第 10 项显示"可测(命令可用，未实测)"即具备断电循环能力；真实重启验证由本流程第二步的 200 次循环完成（每次都是真断电-上电）。如需单独先实测一次，可手工跑（兜底参考）：
```powershell
C:\memtest\tools\ipmitool\ipmitool.exe -I lanplus -H 10.0.0.10 -U root chassis power cycle
```
（服务器重启 = 命令生效；否则 BMC 不支持，别跑 200 次。）

**第二步 · 跑 200 次循环**（总耗时 ≈6.5–7h：1轮全项 1.5–2h + 断电 5h）：
```powershell
cd C:\memtest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-MemtestSuite.ps1 -BatchName srv01-a1-pc -BootMethod SOL -BmcHost 10.0.0.10 -BmcUser root -MaxPasses 1 -RestartLoop 200 -ConfirmSwitch
```
（或用 `config\memtest-suite.conf` 的 `RESTART_LOOP=200`。）

**得到什么**：200 次全部正常初始化、无训练失败。

**日志在哪**：编排机 `results\reports\srv01-a1-pc-powercycle.csv`。

## 流程 6 · 72h ORT 满载老化（第 5 项）

**做什么**：服务器引导菜单选「**72h ORT 无限轮**」预设 + 编排机跑**内置 ORT 模式**，72h 满载老化 + 全程自动测温（间隔按时长动态自适应），结论口径 B。总时长 ≈72h + 10min 缓冲；**不依赖 stress-ng**（无原生 Windows 版）。

**命令**（编排机，内置 ORT 模式）：
```powershell
cd C:\memtest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-MemtestSuite.ps1 -BatchName srv01-a1-ort -BootMethod SOL -BmcHost 10.0.0.10 -BmcUser root -MaxMinutes 4320 -ConfirmSwitch
```
（服务器引导 `memtest-sol.iso` 后在 GRUB 菜单选「72h ORT 无限轮」；`-MaxMinutes 4320` = 72h 时长达标 + 口径 B 结论。）

**温度采样间隔参数**（可选，默认动态自适应）：
- `-TempIntervalMin 0=动态自适应（默认：≤1h→4轮、2-6h→12轮、12h+→60分钟）；>0 显式固定`

**Serial 直连方式（无 BMC）**：无法自动测温，运行 ORT 需追加 `-TempLimitC 0`（关闭温度判据）方可 PASS，或改用 SOL 方式测温。

**得到什么**：72h 内 0 错误、0 ECC、无中断、温度不超阈值；判读 `reports\<批次>-ort-report.csv` 的 `Status=PASS`（口径 B：实际时长 ≥4320 分钟 且 Errors=0 且 EccErrors=0 且 无中断 且 温度 ≤85°C）。FAIL 按原因排查。

**可选：Prime95 整机满载**（**先 Memtest86+ 72h ORT 通过后再决定**）：
- 服务器进 Windows 后跑内置脚本（72h 整机满载，无人值守）：
```powershell
cd C:\memtest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Run-Prime95Stress.ps1 -BatchName srv01-a1-ort-p95 -Minutes 4320 -Mode Blend
```
- 判读 `reports\srv01-a1-ort-p95-prime95-report.csv` 的 `Status=PASS`（实际时长 ≥4320 分钟 且 0 错误 且 非提前退出 且 CPU 活跃；未开始/卡对话框判 FAIL）+ 无死机/重启；
- 温度判据（≤85°C）仅适用于 Memtest86+ ORT 报告；Prime95 脚本报告不含温度列（如需可另行用 HWiNFO64 监控）。
- 软件已内置：`tools\prime95\`（脚本自动调用）。

**日志在哪**：编排机 `reports\<批次>-ort-report.csv`（ORT 结论报告）+ `reports\<批次>-temp.csv`（全程温度采样）+ `results\master_manifest.csv`（累计总表）。

## 流程 10 · 结果归集（服务器 → 编排机）

**做什么**：被测服务器（隔离断网）的结果经 U盘搬运归集到编排机。服务器一键打包 → U盘拷贝 → 编排机一键导入，导入到独立目录 `results\imported\<机器名>\`（累积式：并入不清理、同名覆盖、旧批次独有保留），一眼区分服务器与编排机结果。

**命令**（服务器）：
```powershell
cd C:\memtest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Export-ServerResults.ps1 -MachineName srv01
```
产出 `C:\memtest\results\export\srv01-results-<日期>.zip`（zip 顶层含 建档 csv、master_manifest.csv、reports\、work\、assessment\、cmdlog\、_export-meta.txt）。

**命令**（编排机，U盘里的 zip 拷到本地后）：
```powershell
cd C:\memtest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Import-ServerResults.ps1 -ZipPath <zip 路径>
```
导入 `C:\memtest\results\imported\srv01\`；同 zip 重复导入会提示跳过，追加 `-Force` 可重导（覆盖同名、记录"重导"）。

**得到什么**：编排机 `results\imported\srv01\`（服务器结果独立目录）+ `results\imported\import-log.csv`（导入历史：时间/机器/zip/文件数/来源目录/备注）。

**日志在哪**：两脚本均自动记入各自机器的 `results\cmdlog\commands-<日期>.csv`。

> 附注：机器名默认 `srv01`，其他机器用 `-MachineName <机器名>`；导入目标 `imported\<机器名>\` 自动按此区分多台服务器。
