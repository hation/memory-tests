## 1. 一句话回答

我们的验收测试体系 = **17 项行业测试矩阵**（总纲见 `docs/02-批量压力测试方案.md`），按三层执行：

| 层 | 覆盖项 | 规模 | 当前状态 |
| --- | --- | --- | --- |
| **L1 全量**（每根必测） | 1 SPD校验、2 识别建档、3 Memtest 全地址覆盖、16 混插压力、17 目检+电性 | 1000 根每根都做 | 第 1/2/3/16 可测（软件）；第 17 需万用表 |
| **L2 抽样**（每批抽 N 根） | 4 ECC、5 72h ORT 老化、10 上电掉电循环、15 多平台兼容 | 每 100 根抽 3–5 根 | 第 4 待确认平台；第 5/10/15 可测（软件） |
| **L3 外包**（工程样件） | 6 电压裕量、7 时序/眼图、8 高低温循环、9 湿热 THB、11 ESD、12 振动、13 冲击、14 弯曲 | 每来源类别送 1–3 根 | **当前全部不能测（无硬件）**，见 §4 |

**验收结论 = L1 全量 0 失败 + L2 抽样通过 + L3 样件报告合格**，三者共同构成，缺一不可。

> ⚠️ 当前无相关硬件，L3 八项（6/7/8/9/11/12/13/14）及第 17 项的电性复检、第 4 项的 ECC 平台验证
> 均标注「**当前不能测**」；需要什么硬件、能解决什么问题见 §4。

## 5. 软件可用性校验流程

> 原则：凡是软件项，先校验**这台服务器/编排机上工具是否可用**；不可用的按表做配置/安装。
> 三步走：

### 5.1 第一步：跑环境自检脚本（内置工具全检）

```powershell
# 在离线包根目录运行（无需参数，密码都不需要）
.\scripts\check_env.ps1
```

自检覆盖 6 项：① PowerShell 5.1+ ② 关键脚本齐全 ③ 内置 ipmitool（含 DLL+版本）④ Memtest86+ ISO
⑤ 配置模板 ⑥ SQLite 历史库（可选，需 Python）。输出 `全部 OK` 即可继续；有 `失败` 项按
`docs/12 离线部署与SOL测试手册` 第一章修复。

### 5.2 第二步：跑 BMC/SOL 链路自检（连通性）

```powershell
.\scripts\Diag-Bmc.ps1 -BmcHost 10.0.0.10 -BmcUser root   # 密码运行中提示
```
四步（`mc info` / `chassis status` / `sdr elist` / `sol activate` 短探测）无 Error 即链路 OK；
失败排查见 `docs/15-BMC排查方案.md`。

### 5.3 第三步：能力评估（判断 L2 项能否做）

```powershell
.\scripts\Run-ServerAssessment.ps1 -Local -BmcHost 10.0.0.10 -BmcUser root -MachineName srv01
```
17 项结果逐项给出「可测 / 需 BMC / 需硬件 / 外包」；重点确认：第 4 项 ECC 平台、第 10 项电源控制、
第 15 项多平台。

## 6. memtest-sol.iso 在方案里的定位（重点澄清）

**memtest-sol.iso + Run-MemtestSuite 编排器只承担两件事：**

1. **第 3 项「全地址读写覆盖」的自动化执行**——SOL 远程抓 Memtest86+ 日志、跑满指定轮次自动出逐根报告；
2. **第 16 项「混插压力」的 Memtest 部分**——混插组合跑 Memtest（TM5 部分仍需 Windows 系统级跑）。

**它不覆盖方案的其他部分**：

| 方案组成部分 | 谁来做 | 相关文档 |
| --- | --- | --- |
| 第 1/2 项 识别建档 | `Identify-Memory.ps1`（编排器自动建档） | 01/02 |
| 第 3 项 Memtest 执行 | **memtest-sol.iso + Run-MemtestSuite** | 09/16/17 |
| 第 16 项 TM5/Prime95/OCCT 系统级 | Windows 内手工跑（软件需自行准备，见 §5.4） | 01 |
| 第 17 项目检 | 人工 + 万用表（需采购） | 01/02 |
| 第 4/5/10/15 项 L2 | 服务器 + 监控/断电/多平台（可用 `-MonitorEcc -MonitorTemp -RestartLoop`） | 02/05 |
| 第 6–9、11–14 项 L3 | 外包实验室（当前无硬件，不能测） | 02 |

> 所以：最近围绕 memtest-sol.iso 做的 1/2/4 轮手册，**只是第 3 项（Memtest 全地址覆盖）怎么跑**，
> 不是整个验收方案。整套方案 = 17 项矩阵 + 三层执行，memtest-sol 只是其中第 3 项的加速器。

## 7. 实施路径（怎么一步步做）

```
阶段 0 准备与校验  check_env.ps1 + Diag-Bmc.ps1 + Run-ServerAssessment（§5 三步走）
阶段 1 建档  每根贴唯一 ID → Identify-Memory.ps1 识别分类 → 批次清单       [L1: 1,2]
阶段 2 电性初检  目检 + SPD/容量频率核对（电性复检需万用表到位）              [L1: 1,2,17]
阶段 3 全量压测  memtest-sol 跑全项/快筛（按来源分类定深度）+ 混插 TM5      [L1: 3,16]
阶段 4 抽样可靠  ECC 验证、72h ORT、断电循环、多平台兼容（并行）              [L2: 4,5,10,15]
阶段 5 外包送检  L3 全项同一实验室做齐（每来源类别 1–3 根；无硬件=当前不能测）  [L3: 6–9,11–14]
阶段 6 汇总报告  逐根 pass/fail 总表 + 抽样报告 + 外包报告 → 验收结论
```

详细步骤按场景选手册：
- **单机验收（1 台）**：先 docs/09 配好 SOL → 按 docs/17 跑 1→2→4 轮全项 → 补 TM5/Prime95/OCCT + 温度（docs/01 4.4/4.5，软件需先按 §5.4 配好）
- **批量全检（1000 根）**：docs/01 第 8 章（智能识别 + 混合路由）+ docs/17（快筛）+ `Run-BatchScheduler.ps1`
- **失败件**：docs/01 第 5 章单根隔离 → 换 2/4 轮全项复测（docs/17）

## 9. 常见困惑澄清

| 困惑 | 澄清 |
| --- | --- |
| "memtest-sol.iso 就是整个验收方案？" | **不是**。它只是第 3 项 Memtest 全地址覆盖的执行工具；整套方案是 17 项矩阵 + L1/L2/L3 三层。 |
| "01 和 02 有什么区别？" | 01 = 你当初定的单机/批量验收实施细则（Memtest 4轮 + 系统级压测 + 识别）；02 = 基于朋友 17 项方案整合出的**总纲矩阵**。01 是 L1 的实施细节，02 是全部 17 项的总纲。 |
| "为什么标「当前不能测」？" | 按你的要求：涉及硬件的项一律标注，硬件没到位就不能测。L3 八项 + 第 17 电性复检（万用表）即属此类；要测 → 按 §4 采购或外包。 |
| "软件项怎么确认能用？" | 按 §5 三步走：`check_env.ps1`（内置工具）→ `Diag-Bmc.ps1`（BMC/SOL 链路）→ `Run-ServerAssessment.ps1`（能力评估）→ 按 §5.4 表逐项核对，缺的配好（TM5/HWiNFO/stress-ng 等未随包）。 |
| "1 轮快筛 / 1 轮全项 / 4 轮是什么关系？" | 都是第 3 项 Memtest 的不同深度档位：快筛=前 9 项、全项=13 项、轮次=跑几遍。验收以 4 轮全项为最终口径（docs/17）。 |
| "跑完 memtest 就算验收完了？" | 不算。按三层结论：L1 全量 0 失败（含第 1/2/16/17 项）+ L2 抽样（ECC/ORT/断电/多平台）+ L3 外包报告，才算完整验收。 |
