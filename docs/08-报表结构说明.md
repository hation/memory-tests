# 08 · 报表结构说明

> 状态：[当前有效]（2026-10-22）
> 变更记录：2026-10-22 文档体系编号化（对齐 disk-tests）；工程基建优化更新

> 说明所有输出文件的字段结构、判定逻辑与 MTLOG 事件格式。所有 CSV 均 UTF-8 编码，Excel 可直接打开。

## 1. 输出目录结构

```text
<LogPath>/
├── <批次>-inventory.csv           # 识别建档（Identify-Memory 或编排脚本生成）
├── <批次>-report.csv              # 单批压测汇总（编排脚本生成）
├── master_manifest.csv            # 累计数据库（跨批次合并）
├── raw/                           # 原始 MTLOG / 文本报告备份
│   ├── <批次>.mtlog.txt           # SOL/Serial 抓到的 MTLOG
│   └── MT86P_NN.TXT               # USB 方式保存的文本报告
├── whea_errors.csv                # WHEA 内存错误（-MonitorEcc）
├── <批次>-temp.csv                # IPMI 温度采样（-MonitorTemp）
├── <批次>-powercycle.csv          # 断电循环记录（-RestartLoop）
└── batch-summary-<ts>.csv         # 调度器：每批起止/状态
    all-batches-report-<ts>.csv    # 调度器：全量逐根汇总
```

## 2. 识别清单字段（`<批次>-inventory.csv` / `scripts\Identify-Memory.ps1`）

| 列 | 说明 |
| --- | --- |
| Batch | 批次名 |
| Slot / BankLabel | 槽位标识（DeviceLocator / BankLabel） |
| SerialNumber | SPD 序列号（缺省 = UNKNOWN） |
| PartNumber | 型号（如 HMCG78AGBSA095N） |
| Manufacturer | 厂商 |
| CapacityGB | 容量（GB） |
| SpeedMTs | 频率（MT/s） |
| MemType | 内存类型（DDR4/DDR5/其他） |
| MatchState | 与预期清单匹配结果（匹配/未在清单中/未提供预期清单） |
| Issues | 待复核原因（非 DDR5、无序列号、容量不符等，分号分隔） |
| Status | 分类：正常 / 待复核 |
| TestResult | 压测结果（由压测环节回填） |
| TestDate | 压测日期（由压测环节回填） |

## 3. 压测汇总字段（`<批次>-report.csv` / `scripts\Run-MemtestSuite.ps1`）

| 列 | 说明 |
| --- | --- |
| Batch | 批次名 |
| Slot | 槽位 |
| SerialNumber | 序列号 |
| PartNumber / CapacityGB / SpeedMTs / MemType | 规格信息 |
| MatchState | 预期清单匹配状态 |
| TestDate | 测试日期时间 |
| Passes | 完成的轮次（Memtest86+ `passes`） |
| Errors | 内存错误总数 |
| EccErrors | ECC 错误数（仅 ECC 平台） |
| Result | 判定：**PASS / FAIL / INCOMPLETE**（见第 5 节） |

## 4. MTLOG 事件格式（SOL/Serial 抓取）

每行一条机器可解析事件（`ev=事件` 形式）：

| 事件 | 示例 | 含义 |
| --- | --- | --- |
| start | `ev=start ts=0.0` | Memtest86+ 启动，链路通 |
| info | `ev=info type=system ...` | 系统信息 |
| spd | `ev=spd slot=0 size_mb=16384 type=ddr5 freq=5600 ecc=no mfg=Hynix sku=...` | 槽位 SPD |
| pass_end | `ev=pass_end pass=1 errors=0 status=pass` | 每轮结束 |
| progress | `ev=progress ...` | 进度 tick |
| data | `ev=data addr=0x... expect=0x... actual=0x...` | 错误明细（地址/期望/实测） |
| done | `ev=done passes=4 status=pass` | 全部完成（log 模式自动重启） |

## 5. 判定逻辑

| 条件 | Result |
| --- | --- |
| 收到 `ev=done` 且 `status=pass`、`Errors=0` | **PASS** |
| 任一 `ev=data`（错误）或 `status=fail` | **FAIL**（错误明细进 `raw\` 可查） |
| 超时未收到 `ev=done`（`MaxPasses×90+30` 分钟） | **INCOMPLETE**（检查引导/链路） |

> USB 文本报告模式：解析 `Final Result: PASS/FAIL` + `Passes completed: N` + `Errors: N`，逻辑同上。

## 6. 调度器输出（`scripts\Run-BatchScheduler.ps1`）

**batch-summary** 列：`Batch, Start, End, Status, Error`（Status：OK / FAIL / SKIPPED）

**all-batches-report** 列：与第 3 节相同，追加 `Batch` 来源列，全批次逐根合并。
