## 1. 一句话回答

我们的验收测试体系 = **17 项行业测试矩阵**（总纲见 `docs/02-批量压力测试方案.md`），按三层执行：

| 层 | 覆盖项 | 规模 |
| --- | --- | --- |
| **L1 全量**（每根必测） | 1 SPD校验、2 识别建档、3 Memtest 全地址覆盖、16 混插压力、17 目检+电性 | 1000 根每根都做 |
| **L2 抽样**（每批抽 N 根） | 4 ECC、5 72h ORT 老化、10 上电掉电循环、15 多平台兼容 | 每 100 根抽 3–5 根 |
| **L3 外包**（工程样件） | 6 电压裕量、7 时序/眼图、8 高低温循环、9 湿热 THB、11 ESD、12 振动、13 冲击、14 弯曲 | 每来源类别送 1–3 根 |

**验收结论 = L1 全量 0 失败 + L2 抽样通过 + L3 样件报告合格**，三者共同构成，缺一不可。

## 3. 17 项测什么、怎么测（明细）

### L1 全量（每根必测）

| # | 测试项 | 怎么测 | 工具/设备 | 判据 | 谁负责 |
| --- | --- | --- | --- | --- | --- |
| 1 | SPD 信息校验 | 读 SPD 字段+CRC，与标签/预期清单比对 | `Identify-Memory.ps1` / 编排器建档 | SPD 有效、无 CRC 错误、与标签一致 | 脚本自动 |
| 2 | 基础识别/容量频率 | 核对容量、频率、厂商、序列号 | `Identify-Memory.ps1` / BIOS | 全对 → 通过（防调包） | 脚本自动 |
| 3 | **全地址读写覆盖（Memtest）** | Memtest86+ 全 13 项；按场景跑 1/2/4 轮 × 全项/快筛 | **memtest-sol.iso + Run-MemtestSuite** | 0 错误，记录地址与测试号 | 本工具 |
| 16 | 多通道混插压力 | 混插组合跑 Memtest + TM5 | memtest-sol（Memtest 部分）+ TM5 | 0 错误；单根不稳→隔离 | 本工具+TM5 |
| 17 | 目检 + 电性复检 | 金手指/焊点目检（IPC-A-610）+ 万用表 | 人工 + 万用表 | 无氧化/虚焊/桥连 | 人工 |

### L2 抽样（每批抽 N 根）

| # | 测试项 | 怎么测 | 工具/设备 | 判据 |
| --- | --- | --- | --- | --- |
| 4 | ECC 纠错验证 | 确认 ECC 平台后，Linux `mcelog/edac` 或 Windows WHEA + Memtest86+ `ecc` 参数 | 服务器 + 监控工具 | ECC 生效、无未纠正错误 UE |
| 5 | 72h ORT 满载老化 | 满载 72h（stress-ng `--vm 0 --verify` / stressapptest / TM5 交替）+ 加温 | 服务器 | 72h 内 0 错误、无重启蓝屏 |
| 10 | 上电掉电循环 | `ipmitool chassis power cycle` 自动循环 ≥200 次，每次上电跑首轮 | 编排器 `-RestartLoop` / ipmitool | 全部正常初始化、无训练失败 |
| 15 | 多平台兼容 | Intel/AMD 各 ≥1 台跑识别+快速筛选+满载 2–4h | 各平台服务器 | 0 错误、无兼容异常 |

### L3 外包（工程样件，现有设备做不了）

| # | 测试项 | 设备 |

| 7 | 时序 margin / 信号完整性（眼图，BER 1E-16） | ≥20GHz 示波器 + 眼图软件 |
| 8 | 高低温循环（JESD22-A104） | 高低温试验箱 |
| 9 | 高温高湿偏压 THB（85℃/85%RH） | 恒温恒湿箱 |
| 11 | 静电 ESD（IEC 61000-4-2 / HBM / CDM） | 静电枪 / ESD 测试台 |
| 12 | 机械振动（JESD22-B103） | 振动台 |
| 13 | 机械冲击（JESD22-B110） | 冲击台 |

## 4. memtest-sol.iso 在方案里的定位（重点澄清）

**memtest-sol.iso + Run-MemtestSuite 编排器只承担两件事：**

1. **第 3 项「全地址读写覆盖」的自动化执行**——用 SOL 远程抓 Memtest86+ 日志、跑满指定轮次自动出逐根报告；
2. **第 16 项「混插压力」的 Memtest 部分**——混插组合跑 Memtest（TM5 部分仍需 Windows 系统级跑）。

**它不覆盖方案的其他部分**：

| 方案组成部分 | 谁来做 | 相关文档 |
| --- | --- | --- |
| 第 1/2 项 识别建档 | `Identify-Memory.ps1`（编排器自动建档） | 01/02 |
| 第 3 项 Memtest 执行 | **memtest-sol.iso + Run-MemtestSuite** | 09/16/17 |
| 第 16 项 TM5/Prime95/OCCT 系统级 | Windows 内手工跑 | 01 |
| 第 17 项 目检 | 人工 | 01/02 |
| 第 4/5/10/15 项 L2 | 服务器 + 监控/断电/多平台（可用 `-MonitorEcc -MonitorTemp -RestartLoop`） | 02/05 |
| 第 6–9、11–14 项 L3 | 外包实验室 | 02 |

> 所以：最近我们围绕 memtest-sol.iso 做的 1/2/4 轮手册，**只是第 3 项（Memtest 全地址覆盖）怎么跑**，
> 不是整个验收方案。整套方案 = 上面 17 项矩阵 + 三层执行，memtest-sol 只是其中第 3 项的加速器。

## 5. 实施路径（怎么一步步做）

```
阶段 0 建档  每根贴唯一 ID → Identify-Memory.ps1 识别分类 → 批次清单       [L1: 1,2]
阶段 1 电性初检  目检 + SPD/容量频率核对                                    [L1: 1,2,17]
阶段 2 全量压测  memtest-sol 跑全项/快筛（按来源分类定深度）+ 混插 TM5      [L1: 3,16]
阶段 3 抽样可靠  ECC 验证、72h ORT、断电循环、多平台兼容（并行）              [L2: 4,5,10,15]
阶段 4 外包送检  L3 全项同一实验室做齐（每来源类别 1–3 根）                  [L3: 6–9,11–14]
阶段 5 汇总报告  逐根 pass/fail 总表 + 抽样报告 + 外包报告 → 验收结论
```

详细步骤按场景选手册：
- **单机验收（1 台）**：先 docs/09 配好 SOL → 按 docs/17 跑 1→2→4 轮全项 → 补 TM5/Prime95/OCCT + 温度（docs/01 4.4/4.5）
- **批量全检（1000 根）**：docs/01 第 8 章（智能识别 + 混合路由）+ docs/17（快筛）+ `Run-BatchScheduler.ps1`
- **失败件**：docs/01 第 5 章单根隔离 → 换 2/4 轮全项复测（docs/17）

## 7. 常见困惑澄清

| 困惑 | 澄清 |
| --- | --- |
| "memtest-sol.iso 就是整个验收方案？" | **不是**。它只是第 3 项 Memtest 全地址覆盖的执行工具；整套方案是 17 项矩阵 + L1/L2/L3 三层。 |
| "01 和 02 有什么区别？" | 01 = 你当初定的单机/批量验收实施细则（Memtest 4轮 + 系统级压测 + 识别）；02 = 基于朋友 17 项方案整合出的**总纲矩阵**。01 是 L1 的实施细节，02 是全部 17 项的总纲。 |
| "应该先看哪份？" | 本总览（18）→ 02（总纲）→ 按场景选 01（单机细则）/ 09+17（SOL+逐步压测）。 |
| "1 轮快筛 / 1 轮全项 / 4 轮是什么关系？" | 都是第 3 项 Memtest 的不同深度档位：快筛=前 9 项、全项=13 项、轮次=跑几遍。验收以 4 轮全项为最终口径（docs/17）。 |
| "跑完 memtest 就算验收完了？" | 不算。按三层结论：L1 全量 0 失败（含第 1/2/16/17 项）+ L2 抽样（ECC/ORT/断电/多平台）+ L3 外包报告，才算完整验收。 |
