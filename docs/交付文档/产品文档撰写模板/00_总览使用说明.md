## 二、提炼规则（模板是怎么提炼的）

从源文档提炼出模板的四步规则（新文档类型亦可按此规则扩展）：

**规则 1：结构分层**——把源文档拆为「固定文本 / 占位符 / 可选模块」三层：
- **固定文本**：跨文档逐字不变的（如用户手册五组声明、生产SOP的HSF句式）→ 模板直接固化
- **占位符**：随产品变化的（如型号、规格参数）→ 用 `{{占位符}}` 标注，值取要素字典
- **可选模块**：随产品形态变化的（如 GPU 卡拆装章节、液冷章节）→ 标"（可选）"按需取舍

**规则 2：跨文档比对**——同一类文档取多个样例（如 5 份产品介绍），提取**全部样例的公共章节**为必选骨架，**部分样例特有的章节**为可选模块。差异点即产品形态差异（单路/双路、GPU/非GPU、液冷/风冷）。

**规则 3：数据来源标注**——每个占位符标注数据来源（设计规格/测试报告/BOM/认证证书），并遵循三级可信度（🔴已核实 / 🟡区间估算 / 🟢经验判断）。

**规则 4：一致性清单**——每份模板内置"发布前一致性检查清单"，防止多文档参数漂移。

## 三、使用方式 A：人工填写流程

```
新机型立项
  ↓
1. 收集一手资料（设计规格/测试报告/BOM/认证）—— 填要素字典
2. 按"发布顺序"逐份填模板（03白皮书 → 01/02 → 04 → 05/06 → 07 → 08）
3. 每份发布前跑"一致性检查清单"
4. 升版时：改要素字典 → 同步到受影响文档 → 更新各文档修改记录
```

**关键规则**：**要素字典是唯一事实源**。任何参数变更先在字典改，再同步文档；不允许在单份文档里直接改参数。

## 四、使用方式 B：AI 自动生成工作流

每类模板附一个 JSON Schema（`0X_类型_template.json`），供 AI/程序化生成引擎使用：

```
产品资料库（设计规格/BOM/测试报告）
  ↓ 结构化提取
产品参数 JSON（符合要素字典字段命名）
  ↓ 加载对应 Schema 校验
Schema 通过 → 渲染引擎 + 固定文本模板 → 生成文档草稿
  ↓ 人工评审
发布（一致性检查清单）
```

**AI 生成提示词模板（以 03 白皮书为例）**：

```
你是一名服务器产品文档工程师。请基于以下产品参数JSON，按
[03_技术白皮书_template.json] 的Schema结构，生成技术白皮书全文。
要求：
1. 章节骨架固定（产品概述/产品特点/硬件架构/技术规格/环境规格/软硬件兼容性/系统管理/认证/服务支持）
2. 参数值一律来自参数JSON，不得自行编造；来源冲突以参数JSON为准
3. 每个参数标注数据可信度（🔴/🟡/🟢）
4. 输出Markdown，末尾附"一致性检查清单"自检结果
```

**生成顺序建议**：03 → 01/02 → 04 → 05/06 → 07/08（与人工流程一致）。

## 六、后续扩展建议

1. **新增文档类型时**：按"提炼规则 1~4"操作（结构分层→跨文档比对→数据来源→一致性清单），并补充对应 Schema
2. **产品形态开关表**（建议建立）：机型属性（路数/盘位/GPU/液冷/边缘/存储）× 可选模块的启用矩阵，实现"勾选即生成"
3. **AI 生成引擎**：可将 10 个 Schema + 固定文本模块接入现有文档生成流水线，配合要素字典驱动
