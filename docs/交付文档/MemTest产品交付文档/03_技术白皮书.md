## 1 产品概述

**DDR5 内存条 SOL 全自动验收工具**是一款基于 Windows PowerShell 的 DDR5 内存条**批量压力测试与验收**工具，一句话定位："插满内存，跑一条命令，拿走逐根结论"。

**技术形态**：PowerShell 编排器（Orchestrator）+ Memtest86+ 真实内存测试 + 批量压测报告。PowerShell 负责识别建档、引导、抓日志、解析与判定；Memtest86+ 负责执行真正的内存测试；二者协同产出逐根可追溯的验收报告。

**目标场景**：服务器内存条来料/出货验收、批量压测、产线质检、ORT 老化测试、混插压力测试。

**覆盖范围**：在 17 项验收测试方案中，本工具覆盖其中 8 项（SPD 校验、基础识别、全地址读写、ECC 监控、ORT 72h、重启循环、多平台、混插）；电压裕量、时序、高低温、THB、ESD、振动、冲击、弯曲、目检电性等硬件依赖项维持外包或人工，详见 [需求说明](../../03-PowerShell压测工具需求说明.md) 第 2 节覆盖矩阵。

## 2 产品特点

- **全自动无人值守**：SOL 方式一条命令完成识别建档 → 引导 → 抓日志 → 解析 → 判定 → 汇总报告全链路，出逐根结论，全程无需人工干预。
- **四种引导方式全覆盖**：SOL（BMC 串口网络化，机房批量首选）/ Serial（物理串口线，完全离线）/ USB（U 盘报告，半自动）/ EFI（一次性引导，不破坏默认启动项），按环境选型。
- **智能识别建档与防调包**：读 SPD（序列号/容量/频率/DDR5 判定）+ 预期清单匹配，识别结果与预期不符即标记待复核，从源头杜绝调包。
- **完全离线交付**：ipmitool、Memtest86+、GRUB、便携 Python 等依赖全部内置，零安装、零联网、零配置即可运行。
- **逐根可追溯**：每根条子以序列号关联识别信息与压测结果，合并进 `master_manifest.csv` 累计台账；日志与解析分离，支持 `-ParseOnly` 断点续测。
- **批量调度与结果归集**：批次清单 CSV 驱动逐批自动运行，输出全量逐根总表；支持跨机器结果打包导出与导入合并。
- **附加监控**：WHEA/ECC 错误采集（`-MonitorEcc`）、IPMI 温度采样（`-MonitorTemp`）、断电循环（`-RestartLoop`），一套命令覆盖老化与异常监控。
- **工程化保障**：单源构建（`build.ps1`，VERSION 单一来源）+ 自动化测试（`tests/`）+ 指令记录（cmdlog），可维护、可追溯、可回归。

## 3 技术架构

### 3.1 总体架构

工具采用"编排器 + 测试引擎"两层架构：上层为 PowerShell 编排器，下层为 Memtest86+ 测试引擎。

```text
┌─────────────────────────────────────────────────────────────┐
│  PowerShell 编排器（本工具）                                  │
│  ① 智能识别建档（读 SPD + 预期清单匹配）                       │
│  ② 引导 Memtest86+（SOL / Serial / USB / EFI）               │
│  ③ 捕获输出日志（SOL 会话 / 串口 / U 盘报告）                  │
│  ④ 解析 MTLOG（轮次 / 错误 / 地址 / 测试号）                  │
│  ⑤ 结果判定（PASS / FAIL / INCOMPLETE）                      │
│  ⑥ 汇总报告（合并 master_manifest.csv，逐根可追溯）            │
└─────────────────────────────────────────────────────────────┘
        │ 引导 + 日志
        │ console=ttyS0,115200 log=ttyS0,115200 maxpasses=n testlist=x,y,z
        ▼
  Memtest86+（真实内存测试，UEFI 引导执行全部测试项）
        │ 输出
        ▼
  MTLOG 串口日志 / USB 报告文件
```

六步自动化链路（①→⑥ 即一次完整压测流程）：**识别建档 → 引导 → 抓日志 → 解析 MTLOG → 判定 → 汇总报告**。

### 3.2 分工边界

**本工具不替代 Memtest86+**。真正执行内存测试的是 Memtest86+（覆盖全地址读写、数据保持等测试项）；PowerShell 编排器只负责**编排、捕获、解析、汇总**四件事——引导参数由编排器下发，测试执行由 Memtest86+ 完成，日志解析与判定由编排器承担。因此本工具的能力上限取决于 Memtest86+ 的测试能力，编排器不改变测试本身的行为。

### 3.3 能力覆盖矩阵

在 17 项验收方案中，工具覆盖 8 项：SPD 信息校验（识别建档）、基础识别读取（CIM）、全地址读写覆盖（Memtest86+ 执行）、ECC 纠错验证（WHEA 监控）、ORT 72h 满载老化（长跑 + 满载）、上电掉电重启循环（`maxpasses` 完成自动重启 + IPMI 断电循环扩展）、多平台兼容（同脚本跨平台编排）、混插压力（满槽位混插跑 Memtest86+）。其余硬件依赖项外包或人工，详见 [需求说明](../../03-PowerShell压测工具需求说明.md) 第 2 节。

## 4 运行原理

### 4.1 四种引导方式原理

| 方式 | 原理 | 取日志通道 | 自动化程度 |
| --- | --- | --- | --- |
| **SOL**（BMC 串口网络化） | 服务器 BIOS 开启串口重定向（115200），控制台输出经 BMC 管理口走 IPMI 网络（端口 623）传输；编排机 `ipmitool sol activate` 抓取会话流 | BMC → IPMI 网络 | 全自动无人值守 |
| **Serial**（物理串口线） | null-modem 交叉串口线直连编排机（USB-RS232 转接头），完全离线 | 物理串口线 | 全自动零按键（接好线即可） |
| **USB**（报告导出） | Memtest86+ v9 支持将报告导出到 U 盘，测试完成后编排机读取 U 盘报告文件解析合并 | U 盘文本报告 | 半自动（需人工插拔 + 按键保存） |
| **EFI**（一次性引导） | `bcdedit /set {fwbootmgr} bootsequence {guid}` 创建一次性启动项指向 `mt86plus.efi`，仅当次生效、**不破坏默认启动项**；取日志仍需配合 SOL/Serial/USB | 同所配合通道 | 全自动（需取日志通道） |

> SOL/Serial 使用 log 模式引导参数 `console=ttyS0,115200`、`log=ttyS0,115200`：日志以 MTLOG 机器可解析格式输出，`maxpasses` 跑满后输出 `ev=done` 并自动重启回系统，实现无人值守续批。四种方式选型详见 [引导方式对比评估](../../11-引导方式对比评估.md)。

### 4.2 MTLOG 事件格式

SOL/Serial 抓取的日志为机器可解析格式：每事件一行 `MTLOG ts=<秒> ev=<事件> key=value ...`。

| 事件 | 示例 | 含义 |
| --- | --- | --- |
| `start` | `ev=start ts=0.0` | Memtest86+ 启动，链路通 |
| `info` | `ev=info type=system ...` | 系统信息 |
| `spd` | `ev=spd slot=0 size_mb=16384 type=ddr5 freq=5600 ecc=no mfg=Hynix sku=...` | 槽位 SPD |
| `pass_end` | `ev=pass_end pass=1 errors=0 status=pass` | 每轮结束 |
| `progress` | `ev=progress ...` | 进度 tick |
| `data` | `ev=data addr=0x... expect=0x... actual=0x...` | 错误明细（地址/期望/实测） |
| `done` | `ev=done passes=4 status=pass` | 全部完成（log 模式自动重启） |

### 4.3 判定逻辑

| 条件 | Result |
| --- | --- |
| 收到 `ev=done` 且 `status=pass`、`Errors=0` | **PASS** |
| 任一 `ev=data`（错误）或 `status=fail` | **FAIL**（错误明细进 `raw\` 可查） |
| 超时未收到 `ev=done`（`MaxPasses×90+30` 分钟） | **INCOMPLETE**（检查引导/链路） |

USB 文本报告模式解析 `Final Result: PASS/FAIL` + `Passes completed: N` + `Errors: N`，判定逻辑同上。

### 4.4 附加监控机制

- **WHEA/ECC 监控**（`-MonitorEcc`）：查询 WHEA 事件日志（内存相关 Event ID 18/19/47/0xBC），记录 ECC 纠错/报错，输出 `whea_errors.csv`；无事件时显示"未检测到"。
- **IPMI 温度采样**（`-MonitorTemp`）：经 IPMI 传感器读取 DIMM 温度，输出 `<批次>-temp.csv`；内置 ORT 模式支持动态测温间隔（0=自动）。
- **断电循环**（`-RestartLoop`）：经 IPMI `chassis power cycle` 执行物理断电循环，输出 `<批次>-powercycle.csv`（前置电源风险警示，见第 9 节）。

## 5 功能模块详解

| 指令记录 | `scripts\Start-CommandLog.ps1` / `Stop-CommandLog.ps1` | 会话级转录（可选）；所有脚本自动写 `results\cmdlog\commands-<日期>.csv`（常开、密码打码） |

各模块职责简述：

- **核心编排**（`Run-MemtestSuite.ps1`）：编排器主脚本，串联识别建档 → 引导（四种方式）→ 抓日志 → 解析 MTLOG → 判定 → 输出逐根报告；内置 ORT 长跑模式（全程测温、口径 B 结论）；日志与解析分离，`-ParseOnly` 支持从已有日志断点续解析。
- **批量调度**（`Run-BatchScheduler.ps1`）：以批次清单 CSV 为驱动，逐批调用核心编排自动运行，遇错可 `-ContinueOnError` 继续，最终输出全量逐根总表与批次汇总；`-DryRun` 支持先预览再实跑。
- **识别建档**（`Identify-Memory.ps1`）：经 CIM 读取 `Win32_PhysicalMemory`（SMBIOSMemoryType=34 判定 DDR5），读序列号/容量/频率/厂商，与 `-ExpectedCsv` 预期清单匹配，输出 `<批次>-inventory.csv`，识别结果异常（非 DDR5、无序列号、容量不符等）标记待复核。
- **服务器评估**：对被测服务器做 17 项测试可行性评估，带内（CIM）与带外（BMC/IPMI）双通道采集，角色化三态判定，输出仅作排期参考、不消费测试数据；评估合并步骤可选，不影响主流程。
- **BMC 诊断与防护**：`Diag-Bmc.ps1` 一键诊断 BMC 连通与 SOL 链路；`Set-BmcStaticIp.ps1` 支持 BMC 静态 IP 查询/恢复，用于网络异常后的防护与恢复。
- **环境自检**（`check_env.ps1`）：部署后首行打印工具版本，核对 PowerShell/ipmitool/内置依赖可用性，是部署前的一键自检入口。
- **菜单版 ISO**：将 Memtest86+ 封装为 GRUB 菜单版 `memtest-sol.iso`，预设测试档位、20 秒无操作自动进默认档位，供人工/半自动场景直接用 ISO 开测；`Smoke-MemtestIso.ps1` 经 QEMU/OVMF 虚拟引导冒烟验证 ISO 可引导性。
- **整机满载**：Prime95 无值守 torture 封装，Windows 整机满载压测，作为 ORT 的增强手段（加压/加温仍需外部手段）。
- **结果归集**：`Export-ServerResults.ps1` 将单机结果打包导出，`Import-ServerResults.ps1` 在另一机器导入合并，支撑多机并行压测后的统一归集。
- **任务清单**：17 项测试执行清单的进度追踪，提供总览视图，主流程自动勾选推进。
- **指令记录**：会话级转录开关（`Start/Stop-CommandLog.ps1`）；所有脚本自动写 `results\cmdlog\commands-<日期>.csv`（常开、密码打码为 `***`），排查历史操作先看这里。
- **历史库**：`db/` 为可选功能，SQLite（纯标准库 sqlite3、WAL 模式、幂等建表）三段式表结构（batches/entities/runs），按序列号跨批次追踪历史，重复导入自动跳过；剥离该目录不影响 PowerShell 主流程。
- **单源构建**：`build.ps1` 一键同步离线包，`-Zip` 打交付包（先删旧包再建新包并校验时间戳与 hash），VERSION 单一来源。

## 6 规格参数

### 6.1 运行环境

| 项 | 要求 |
| --- | --- |
| 编排机系统 | Windows 10 / Windows Server 2016+ |
| PowerShell | 5.1+（系统自带，首选 `powershell.exe`，兼容 `pwsh`） |
| 网络 | 编排机可 ping 通服务器 BMC 管理 IP（端口 623）；无需互联网 |
| 被测服务器 | 带 BMC/IPMI + 内存槽；开启 BMC SOL + BIOS 串口重定向（**115200**） |
| 被测内存 | DDR4 / DDR5（Memtest86+ v9 支持） |

### 6.2 内置依赖（免联网免安装）

| 依赖 | 版本 | 位置 | 用途 |
| --- | --- | --- | --- |
| ipmitool | 1.8.18（含依赖 DLL） | `tools\ipmitool\` | SOL 抓流 / 断电循环 / 温度读取，脚本自动发现 |

可选外部依赖：Rufus（制作 USB 引导盘）；Serial 方式需 null-modem 交叉串口线 + USB-RS232 转接头；`db/` 历史库需 Python 3。

### 6.4 输出文件结构

```text
<LogPath>/（默认 results\，可用 -LogPath 重定向）
├── <批次>-inventory.csv           # 识别建档（识别环节生成）
├── <批次>-report.csv              # 单批压测汇总（判定环节生成）
├── master_manifest.csv            # 累计台账（跨批次合并，逐根可追溯）
├── raw/                           # 原始 MTLOG / 文本报告备份
│   ├── <批次>.mtlog.txt           # SOL/Serial 抓到的 MTLOG
│   └── MT86P_NN.TXT               # USB 方式保存的文本报告
├── whea_errors.csv                # WHEA 内存错误（-MonitorEcc）
├── <批次>-temp.csv                # IPMI 温度采样（-MonitorTemp）
├── <批次>-powercycle.csv          # 断电循环记录（-RestartLoop）
├── batch-summary-<ts>.csv         # 调度器：每批起止/状态
├── all-batches-report-<ts>.csv    # 调度器：全量逐根汇总
├── all-batches-summary-<ts>.txt   # 调度器：批次/逐根汇总文本（UTF-8 BOM）
└── cmdlog\commands-<日期>.csv     # 指令记录（常开，密码打码）
```

> 所有 CSV 为 UTF-8 编码，Excel 可直接打开；汇总文本为 UTF-8 BOM。

### 6.5 报告字段

**识别清单（`<批次>-inventory.csv`）**：`Batch / Slot / BankLabel / SerialNumber / PartNumber / Manufacturer / CapacityGB / SpeedMTs / MemType / MatchState / Issues / Status / TestResult / TestDate`。其中 `Issues` 为待复核原因（非 DDR5、无序列号、容量不符等，分号分隔），`Status` 分正常/待复核，`TestResult` 由压测环节回填。

**压测汇总（`<批次>-report.csv`）**：`Batch / ToolVersion / Slot / SerialNumber / PartNumber / CapacityGB / SpeedMTs / MemType / MatchState / TestDate / Passes / Errors / EccErrors / Result`。`ToolVersion` 读根 VERSION，逐行可追溯工具版本；`EccErrors` 仅 ECC 平台有值。

**调度器输出**：`batch-summary-<ts>.csv` 列为 `Batch / Start / End / Status / Error`（Status：OK / FAIL / SKIPPED）；`all-batches-report-<ts>.csv` 与压测汇总同列并追加 Batch 来源列，全批次逐根合并；`all-batches-summary-<ts>.txt` 为人类可读汇总（Result 各档计数与时间区间），无逐根报告时跳过生成。

## 8 测试验证

本工具内置多层验证手段，用于回归与交付前确认（验证能力与手段如下，不涉及具体结果数字）：

- **自动化测试套件（`tests/`）**：覆盖共享库（`test-lib.ps1`）、参数校验（`test-args.ps1`）与历史库（`test_db.py`），对解析逻辑、参数合法性、SQLite 幂等性做回归验证。
- **菜单版 ISO 冒烟（`Smoke-MemtestIso.ps1`）**：经 QEMU/OVMF 虚拟引导启动 `memtest-sol.iso`，验证 ISO 可引导性与默认档位自动进入行为，构建产物交付前必跑。
- **环境自检（`check_env.ps1`）**：首行打印工具版本，核对 PowerShell 版本、内置 ipmitool 可用性与脚本可解析性，是部署与排障的第一步。
- **判定逻辑验证**：按验收标准验证——指定轮次跑满且 0 错误 → PASS 并写入报告；人为制造错误 → 判 FAIL 且错误明细进 `raw\` 可查；超时未完成 → 判 INCOMPLETE；SOL 断连一次后自动重连补抓、不丢结论；`Ctrl+C` 中断后已解析结果保留、重跑可续测。
- **链路验证**：SOL 配置正确后 `ipmitool sol activate` 可见 BIOS 启动输出（看不到即重定向/波特率未配对），作为引导链路通断的判据。

## 9 安全与可追溯

- **凭据安全**：BMC 密码在运行中提示输入，不落命令行与脚本；指令记录 cmdlog 对密码打码为 `***`。
- **指令记录**：所有脚本自动写 `results\cmdlog\commands-<日期>.csv`（常开、CSV 格式），会话级转录可用 `Start/Stop-CommandLog.ps1`；排查历史操作以 cmdlog 为准。
- **引导配置安全**：EFI 一次性引导经 `bcdedit /set {fwbootmgr} bootsequence {guid}` 创建，仅当次生效、不破坏系统默认启动项；引导/重启类操作需 `-ConfirmSwitch` 显式确认。
- **断点续测**：日志与解析分离，`-ParseOnly` 仅解析已有日志即可续测/复核；`Ctrl+C` 安全停止并保留已解析结果。
- **断电循环警示**：`-RestartLoop` 物理断电循环前置电源风险警示（v19 起），操作前须确认供电与设备安全。
- **逐根可追溯**：每根条子以序列号关联识别信息与压测结果，合并进 `master_manifest.csv` 累计台账；`report.csv` 带 `ToolVersion` 列，逐行可追溯工具版本，历史遗留旧行合并后该列自动为空（列集合以本次报表为准）。

### 10.2 版本来源

版本号**唯一来源**为仓库根 `VERSION` 文件（当前 v20）；脚本统一经 `Get-AppVersion`（`scripts\lib_common.ps1`）读取，报告 `ToolVersion` 列亦取自该处。改版本只改该文件，勿在脚本中硬编码。

### 10.3 维护约定

- `docs/` 下文档以 `[当前有效]` 标记当前生效版本，失效/废弃需同步改标。
- 打包触发条件 = 逻辑代码有调整（脚本/库/ISO 等代码产物变更）或用户主动要求发布新版本包，才执行 `scripts\build.ps1 -Zip`；纯文档/配置小改动不打包（下次打包自动同步进 kit）。打包时先删除旧 `memtest.zip` 再创建新包，并校验 zip 时间戳与包内关键文件 hash。
- 服务器能力评估的合并步骤（`Run-ServerAssessment -MergeInband/-MergeOob`）为可选：已人工确认能力项时可跳过，其输出仅排期参考、无脚本消费。
