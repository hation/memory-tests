## 2. 本期重点（v20 与 v19）

### v20（2026-10-28）—— ORT 动态测温 + SOL 残留会话修复

**为什么做**：72 小时 ORT 老化测试跨昼夜运行，内存温度随负载与机房环境持续变化，固定间隔测温要么采样过频徒增开销、要么过疏错过温度峰值；同时长时运行后 SOL 会话偶有残留连接，会导致新一批次开测时抓不到输出。

**做了什么**：测温间隔支持动态调整（设为 0 时自动按测试阶段确定采样节奏），并修复 SOL 残留会话问题，保证新会话正常建立。

**价值**：长时老化测试全程更省心，温度监控贴合实际、SOL 链路更稳定，减少中途人工干预，向"无人值守跑完 ORT"再进一步。

### v19（2026-10-28）—— BMC 前置体检与网络防护

**为什么做**：批量压测开工前，服务器 BMC 的状态直接决定测试能否顺利开始；断电循环测试会反复通断电源，若 BMC 网络不稳或配置不当，存在测试中断的风险。

**做了什么**：新增 BMC 前置体检（`Invoke-BmcPreflight`）与 BMC 静态 IP 设置/恢复（`Set-BmcStaticIp`），断电循环前增加电源风险警示；SOL 捕获加固（断连检测、自动重连、四查指引）。

**价值**：把风险前置拦截——开工前先体检、网络可防护、抓取更稳，出问题时按指引快速定位，批量测试的可靠性整体抬高一档。

## 3. 历史版本明细

### 3.1 v1–v2（2026-10-22）—— 工程基建

新增能力：

- 单源构建 `build.ps1`
- `VERSION` 单一来源
- 环境自检 `check_env.ps1`
- 自动化测试框架

阶段意义：为工具立起「版本可管、环境可查、质量可测」的工程底座，后续所有功能都在这套基座上生长。

### 3.2 v5–v6（2026-10-22）—— 离线部署

新增能力：

- 离线包落地（`memtest/`）
- 输出目录重构（`results\` 独立于脚本）

阶段意义：让工具真正「零安装、零联网」即可交付，且数据输出与脚本代码分离，不再混在一起。

- 服务器能力评估（17 项可行性）

阶段意义：先摸清被测服务器能不能测、怎么测，把排查路径与行业术语沉淀成文档，为后续自动化铺平道路。

## 4. 版本维护约定

| 约定项 | 说明 |
|---|---|
| **VERSION 单一来源** | 版本号唯一来源为仓库根目录 `VERSION` 文件；改版本只改该文件，不在脚本中硬编码。 |
| **Get-AppVersion 统一读取** | 脚本统一经 `Get-AppVersion`（`scripts\lib_common.ps1`）读取版本号，保证展示与报告中的版本信息一致。 |
| **check_env.ps1 首行核对** | 环境自检脚本首行打印工具版本并核对依赖可用，是运行前的版本核对入口。 |
| **打包纪律（交付 zip）** | 打包触发条件 = 逻辑代码有调整（脚本/库/ISO 等代码产物变更）或主动要求发布新版本包时，才执行 `scripts\build.ps1 -Zip`；纯文档/配置小改动不打包（下次打包时自动同步进 kit）。打包时先删旧 `memtest.zip` 再建新包（build.ps1 已内置先删后建）；打包后校验 zip 时间戳为当前、包内关键文件与仓库 hash 一致，不一致视为打包失败重新打包。 |
| **文档同步** | 交付文档升版时同步更新本表与要素字典第 2 节（先改字典、再同步各文档），保证版本演进脉络在全套交付文档中一致。 |
